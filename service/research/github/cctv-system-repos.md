# CCTV systems and zero-shot software audit

**Audit date: 21 October 2026. Static source/asset audit only; no package installation, repository execution, model loading, inference, training or live-service changes.** Read `PROTOCOL.md` first. Public GitHub source/config files and metadata were fetched into memory; checkpoint bodies were not downloaded. GitHub API was rate-limited, so revisions came from `git ls-remote ... HEAD`, directory inventories from GitHub HTML, and code from commit-pinned raw URLs. HTTP HEAD checks establish accessibility/declared size, not checkpoint integrity or successful loading.

## Decision

**Do not select SAF-DETR as a fight detector.** Its released API equates more than two detections with violence; its live implementation assigns fight labels through person confidence/global optical-flow heuristics, can silently fall back to motion contours, and caps transformer detections at ten. No trained SAF checkpoint is in the inspected checkpoint directory. Low-light enhancement and a crowd-oriented name do not supply measured fight recognition.

There are **not 2–3 verified turnkey systems satisfying NIVRA's operating requirements** in this audit. The defensible comparison shortlist is:

1. **MMAction2 AVA SlowOnly + person detector:** strongest released software path for actual per-person action localization; independently stage compatibility and checkpoint terms before parent-run comparison.
2. **Official OpenAI CLIP ViT-B/32:** accessible, compact zero-shot **research control**, replacing the unlicensed/buggy sukhitashvili wrapper rather than adopting its code. It is an image semantic baseline, not a motion-aware fight detector or a recommended deployment.
3. **HashemIlI SCVD CNN-LSTM:** concrete downloadable checkpoint and temporal event implementation, but **rights-blocked/view-only**. Inspectable comparison prospect only; no reuse or run recommendation until permission/terms are resolved. Its person boxes are explicitly not fight localization.

Retain community X3D-M live. Nothing here demonstrates fewer missed events or fewer false alerts than that baseline. Existing MC3 and VID experiment results remain development evidence under the protocol, not a crowd/night benchmark.

## SAF-DETR: implementation contradicts the strongest claims

- [API lines 82–103 and 205–218](https://github.com/RUTejas/SAF-DETR/blob/cf7a902aaa0ba1595906d5e2de56c6ab33b56681/deployment/api.py#L82): builds a one-person-class model, disables temporal memory, continues without trained detector weights, names all accepted detections person, and uses `len(detections) > 2` as its violence decision. This would make a successful crowded-person detector trigger on ordinary crowds.
- [Live path lines 65–95](https://github.com/RUTejas/SAF-DETR/blob/cf7a902aaa0ba1595906d5e2de56c6ab33b56681/live_predict.py#L65): explicitly constructs with `pretrained=False`, accepts missing checkpoints, and also continues after checkpoint-load exceptions. [Lines 241–286](https://github.com/RUTejas/SAF-DETR/blob/cf7a902aaa0ba1595906d5e2de56c6ab33b56681/live_predict.py#L241) cap NMS output at ten; fight status derives from global flow energy or high person confidence. Model exceptions are swallowed. The [fallback](https://github.com/RUTejas/SAF-DETR/blob/cf7a902aaa0ba1595906d5e2de56c6ab33b56681/live_predict.py#L169) can insert a default central box with confidence 0.88 on initial static background setup. These are neither learned fight scores nor reliable localization.
- [Model lines 172–243](https://github.com/RUTejas/SAF-DETR/blob/cf7a902aaa0ba1595906d5e2de56c6ab33b56681/models/SAF_DETR/complete_model.py#L172) expose person/background logits and normalized box outputs; [temporal memory is gated on `self.training`](https://github.com/RUTejas/SAF-DETR/blob/cf7a902aaa0ba1595906d5e2de56c6ab33b56681/models/SAF_DETR/complete_model.py#L374), so enabling that flag does not establish temporal inference.
- [Checkpoint directory](https://github.com/RUTejas/SAF-DETR/tree/cf7a902aaa0ba1595906d5e2de56c6ab33b56681/checkpoints) contains `.gitkeep`, not `saf_detr/best.pth`. No downloadable trained SAF asset was verified. The [README results](https://github.com/RUTejas/SAF-DETR/blob/cf7a902aaa0ba1595906d5e2de56c6ab33b56681/README.md#L259) explicitly call the headline numbers **targets**, while providing an ablation table without inspected reproducibility artifacts. Its [citation](https://github.com/RUTejas/SAF-DETR/blob/cf7a902aaa0ba1595906d5e2de56c6ab33b56681/README.md#L330) says under review; no independent accepted IEEE record was established by title searches. Do not describe it as an accepted IEEE detector.
- Additional static defects: [API preprocessing/postprocessing](https://github.com/RUTejas/SAF-DETR/blob/cf7a902aaa0ba1595906d5e2de56c6ab33b56681/deployment/api.py#L105) promotes arrays to float64 through float64 mean/std; keeps the maximum over person **and background** without rejecting background; treats normalized box coordinates as pixel corners without the live path's conversion. These are source deductions, not executed reproductions.

Code is [MIT](https://github.com/RUTejas/SAF-DETR/blob/cf7a902aaa0ba1595906d5e2de56c6ab33b56681/LICENSE); checkpoint terms cannot be assessed without a checkpoint. Named dataset support is not proof those datasets trained a released model. CLAHE is an image enhancement, not evidence of real near-IR or night generalization. No GTX 1660 Ti experiment is justified before these fundamental blockers are fixed.

## Zero-shot systems: semantic scores versus temporal recognition

### sukhitashvili wrapper / official CLIP control

[model.py](https://github.com/sukhitashvili/violence-detection/blob/b16770faa39d5cf1284ff4175793efabfddb4dc0/model.py) loads CLIP ViT-B/32, prepends `a photo of ` to YAML labels, and returns the highest normalized image/text cosine similarity above 0.23. It takes the **absolute value** of that similarity; this is not a calibrated probability. [run.py](https://github.com/sukhitashvili/violence-detection/blob/b16770faa39d5cf1284ff4175793efabfddb4dc0/run.py#L17) passes OpenCV BGR directly despite the model's RGB contract. There is no motion model, interaction box, tracker, or event boundary policy. [Requirements](https://github.com/sukhitashvili/violence-detection/blob/b16770faa39d5cf1284ff4175793efabfddb4dc0/requirements.txt) pin old Torch/Python-era dependencies, include `pyheif`, and use `clip-by-openai` rather than a pinned official CLIP source. No licence file was found in the inspected root; `LICENSE` returned 404. Do not copy this wrapper as licensed code.

Use the official source pin above for a separately implemented offline control:

- [Canonical asset registry and transform](https://github.com/openai/CLIP/blob/d05afc436d78f1c48dc0dbf8e5980a9d471f35f6/clip/clip.py#L36): [ViT-B-32.pt](https://openaipublic.azureedge.net/clip/models/40d365715913c9da98579312b702a82c18be219cc2a73407c4526f58eba950af/ViT-B-32.pt), HEAD 200, **353,976,522 bytes**. Expected SHA256 encoded in the official URL: `40d365715913c9da98579312b702a82c18be219cc2a73407c4526f58eba950af`; not locally recomputed.
- RGB → bicubic resize of short side to model resolution → center crop (224 for ViT-B/32) → tensor `[0,1]` → mean `(0.48145466,0.4578275,0.40821073)`, std `(0.26862954,0.26130258,0.27577711)`. Center cropping can omit lateral interactions in widescreen CCTV; it is not full-scene coverage.
- No fixed binary class order. The ordered prompt list defines output indices. The wrapper's [YAML](https://github.com/sukhitashvili/violence-detection/blob/b16770faa39d5cf1284ff4175793efabfddb4dc0/settings.yaml) has 18 prompts, with fight-related indices 2, 4 and 12 (zero-based), among scene/context distractors. Freeze prompts, aggregation and thresholds before scoring; neither 0.23 cosine nor prompt-softmax is a validated fight probability.
- Official code [MIT](https://github.com/openai/CLIP/blob/d05afc436d78f1c48dc0dbf8e5980a9d471f35f6/LICENSE). No independent checkpoint-specific licence was established beyond the release/repository documentation. Training images are not a reusable released/licensed CCTV dataset. The [model card](https://github.com/openai/CLIP/blob/d05afc436d78f1c48dc0dbf8e5980a9d471f35f6/model-card.md#L32) describes research use, deployment as out of scope, and certain surveillance uses as always out of scope; this is a material suitability statement, separately from the code licence.

**Hardware inference:** one small image batch is plausibly within 6 GB; no local measurement. Scoring 50–100 crops multiplies work and may lose pair context. No true-IR/night performance evidence was established.

### ALOOHA track/crop pipeline

This is more useful as engineering than as proof of temporal model quality. [Action recognition](https://github.com/ALOOHA-hub/Violence-Action-Detection/blob/191facd74d4a176067a9376b856ad624b981a8f0/src/core/analysis/action_rec.py#L70) averages per-frame CoCa image/text softmax scores; **frame permutation leaves that aggregation unchanged**. An eight-frame input does not make it a learned motion encoder. [Configuration](https://github.com/ALOOHA-hub/Violence-Action-Detection/blob/191facd74d4a176067a9376b856ad624b981a8f0/configs/config.yaml) includes gun/fall/injury prompts outside this task. Its `ors_threshold` spelling differs from code's `osr_threshold`, so the intended 0.35 value falls back to 0.25.

[YOLO/ByteTrack](https://github.com/ALOOHA-hub/Violence-Action-Detection/blob/191facd74d4a176067a9376b856ad624b981a8f0/src/core/perception/detector.py) supplies track boxes. [Dispatch](https://github.com/ALOOHA-hub/Violence-Action-Detection/blob/191facd74d4a176067a9376b856ad624b981a8f0/src/pipelines/rapid_flow.py#L198) chooses one ready ID, with an analysis queue capacity of one. Round-robin intent is present, but no maximum-age/deadline/coverage accounting for 100 tracks was established. Dropped ready clips and changing ID sets require explicit measurement. Local Qwen/Ollama is instantiated as another pipeline stage; cloud alternatives are outside authorization.

[Models directory](https://github.com/ALOOHA-hub/Violence-Action-Detection/tree/191facd74d4a176067a9376b856ad624b981a8f0/models) only contains `NOTE.txt`; `coca_l14.bin` has no verified exact source/hash in the inspected configuration. Code is [MIT](https://github.com/ALOOHA-hub/Violence-Action-Detection/blob/191facd74d4a176067a9376b856ad624b981a8f0/LICENSE.txt), not a grant for YOLO, CoCa, Qwen weights or training media. The combined multi-model stack is a poor initial 6 GB choice; CoCa-alone fit and Windows compatibility remain unmeasured. Do not run its installer: [requirements](https://github.com/ALOOHA-hub/Violence-Action-Detection/blob/191facd74d4a176067a9376b856ad624b981a8f0/requirements.txt) globally replace the package index with a CUDA wheel index and leave most versions open.

## Concrete temporal candidate with a rights block: SCVD

[Source core](https://github.com/HashemIlI/Smart-City_CCTV_Violence_Detection/blob/c93325b35c4797b879c17873be40ac398ec26de3/SCVD_Professional_GUI.py#L14) defines `[Normal, Violence, Weaponized]`, a frozen ResNet18 feature extractor, two-layer LSTM (512→256) and three-way FC output. It reads 16 timestamp-spaced RGB frames per window, PIL-resizes 112² and applies ImageNet mean/std. Default windows are 2 s, stride 1 s; neighbouring probabilities use a symmetric 0.25/0.5/0.25 smoother before event merging. That smoother consumes a future window and is offline/noncausal as written. The CUDA batch default is 16 windows; begin with one in a future adapter, not that default.

[LFS pointer](https://github.com/HashemIlI/Smart-City_CCTV_Violence_Detection/blob/c93325b35c4797b879c17873be40ac398ec26de3/best_model.pth): **50,179,854 bytes**, SHA256 **`3f57b1f32837b0e99893108ec20a2f2dcac21ad875b5f2e4d10b8a69517e7958`**. [Pinned media URL](https://media.githubusercontent.com/media/HashemIlI/Smart-City_CCTV_Violence_Detection/c93325b35c4797b879c17873be40ac398ec26de3/best_model.pth) returned HEAD 200 with matching declared size; body/hash/load unverified.

**Rights blocker:** the [README licence statement](https://github.com/HashemIlI/Smart-City_CCTV_Violence_Detection/blob/c93325b35c4797b879c17873be40ac398ec26de3/README.md#L571) explicitly says no licence, all rights reserved, view-only. This covers neither a reusable code grant nor checkpoint permission. SCVD footage has separate source-author terms. Do not contact authors under this task. No run/adoption approval follows from public LFS availability.

Keep `Violence` separate from `Weaponized`; summing them would broaden the unarmed target. The author's reported best-test checkpoint selection is not an untouched evaluation protocol. Their README also reports poor full-clip violence transfer, reinforcing the need for matched-window tests rather than a headline comparison. YOLO person overlays are expressly scene context, not attribution of a fight to a person. A batch-one model of this size plausibly fits 6 GB, but capacity, latency and 100-person efficacy are unverified.

## Actual localization software: MMAction2 AVA

This is the clearest alternative to whole-frame binary scores. The [video demo](https://github.com/open-mmlab/mmaction2/blob/a5a167dff2399e2d182a60332325f9c0d4663517/demo/demo_spatiotemporal_det.py) runs a person detector at clip centers and applies a shared video backbone plus RoI action head to person proposals. It produces person boxes with **multilabel action scores**, not a single scene prediction and not identities. [AVA label map](https://github.com/open-mmlab/mmaction2/blob/a5a167dff2399e2d182a60332325f9c0d4663517/tools/data/ava/label_map.txt): **64 fight/hit (a person)**; 66 grab, 68 hand shake, 70 hug and 76 push are distinct labels. Preserve dataset IDs: these are not zero-based indices into the displayed 60-line subset. Fight policy must be fixed; do not automatically label every grab/push/martial-art score a fight.

Action validation resizes short side to 256 without crop/flip; raw-pixel mean `[123.675,116.28,103.53]`, std `[58.395,57.12,57.375]`; C,T,H,W tensor. Demo manually normalizes with `to_rgb=False`, so preserve its actual decoded channel path instead of mixing in another adapter's RGB transform. Person detection uses its separate RGB-converting preprocessor and aspect-preserving `(1333,800)` resize. Eight frames spaced eight source frames have an FPS-dependent time span; the demo needs a 64-frame temporal window. It is not equivalent to NIVRA's four seconds without recording/matching sample times.

**Crowd risks:** default detector confidence is high (0.9); final detector limit 100 includes non-person classes before filtering. Raising this cap is only a configuration change, not proof of recovering all 100 people. Occluded/missed person proposals cannot receive a fight score. The demo iterates all surviving proposals; its `max_num=5` is labels drawn **per person**, not a five-person processing cap. Shared-backbone RoIs offer a more credible compute foundation than 100 separate full video backbones, but this is an engineering inference, not a measured speedup here.

**Integration:** video demo extracts/retains the full input; use only short parent-selected clips initially. Do not treat it as production streaming. Official [installation documentation](https://github.com/open-mmlab/mmaction2/blob/a5a167dff2399e2d182a60332325f9c0d4663517/docs/en/get_started/installation.md) names Windows support, but compatible Torch/MMCV CUDA ops/MMDetection/MMEngine wheels must be pinned in an isolated environment. Demo uses `np.Inf`, so NumPy 2 compatibility must be addressed or NumPy <2 fixed. Batch-one, short-side 256 action inference plausibly fits 6 GB; detector allocations, 100 RoIs, concurrent live usage and real latency remain unmeasured. Do not claim 1080p inference merely because the decoder accepts 1080p and then downsizes it.

[Apache-2.0 code licence](https://github.com/open-mmlab/mmaction2/blob/a5a167dff2399e2d182a60332325f9c0d4663517/LICENSE) is verified. Separate checkpoint-specific commercial/surveillance permission was not established in this audit. AVA/Kinetics movie/web training sources and COCO image rights do not become licensed CCTV footage through the framework licence. Review those terms before adopting weights; do not infer night or crowd qualification from AVA mAP.

## CCTV anomaly research: localization must be named precisely

[VadCLIP](https://github.com/nwpu-zxr/VadCLIP/tree/c41067f07d252efcda18008bea367886070c33b0) is genuine author-released AAAI research with [Apache-2.0 code](https://github.com/nwpu-zxr/VadCLIP/blob/c41067f07d252efcda18008bea367886070c33b0/LICENSE), not merely a dashboard. However, [XDDataset](https://github.com/nwpu-zxr/VadCLIP/blob/c41067f07d252efcda18008bea367886070c33b0/src/utils/dataset.py#L35) reads pre-extracted `.npy` features, and [xd_test.py](https://github.com/nwpu-zxr/VadCLIP/blob/c41067f07d252efcda18008bea367886070c33b0/src/xd_test.py#L92) scores temporal segments/classes. Its ordered XD mapping is normal, fighting, shooting, riot, abuse, car accident, explosion. It is **trained weakly supervised adaptation**, not the unfitted CLIP control, and temporal fighting scores are not person/interaction boxes. README checkpoint/feature links lead to OneDrive/Baidu; exact model bytes/hash, preprocessing-to-source-time correspondence and a one-file raw-video pipeline were not verified. No download or run was attempted. Defer rather than mistake it for a deployable localization system.

The author-hosted [2019 localization-guided fight paper](https://weiyaolin.github.io/pdf/LocalizationGuided.pdf) describes optical-flow active regions and detection-guided alignment, but this audit did not locate a verified official runnable checkpoint/code release. Paper existence does not supply an executable candidate. MMAction2 supplies actual boxed fight/hit scores; ALOOHA supplies tracked crop association; SCVD supplies only temporal events plus unrelated person overlays. Keep those three notions separate.
