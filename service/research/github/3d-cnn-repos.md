# Released 3D CNN fight models: source and asset audit

Audit date: 21 October 2026. Read `PROTOCOL.md` first. Research only: no repository code executed, packages installed, complete model downloaded, inference/training/GPU job launched, or service changed. The only local output of this task is this report.

## Decision

Stage **two new model artifacts**, in this order: **original Flow Gated Network (FGN)**, then **Fightdet grayscale + optical flow**. Keep the existing **MC3-18 as a reproducibility control**, not a newly discovered alternative. These are the two inspected alternatives with concrete released model files plus enough source to build an offline adapter. They are **not verified turnkey Windows executables**, and neither has established deployment rights or NIVRA performance. If “truly runnable” requires a successful local load and forward pass, this research-only task establishes **zero newly runtime-verified models**.

Do not promote either or start another training run from README percentages. Both alternatives add a motion-stream hypothesis worth testing; they are not simply another ImageNet frame head. Their shared ancestry means they are not two independent demonstrations of generalization.

The local [comparison](../../evaluation/FIGHT-MODEL-COMPARISON.md) confirms that X3D-M and MC3 matched 2/3 original diagnostic events, with one extra MC3 shadowboxing alert. Those development recordings do not measure crowd/night transfer. The latest fine-tune's training fit does not change this evidence boundary.

### Specific source findings that affect reproducibility

- **MohamedSebaie:** [utility source](https://github.com/MohamedSebaie/Fight_Detection_From_Surveillance_Cameras-PyTorch_Project/blob/a27adffec6651c10639b5b453e0df8564b9be298/UtilsFiles/Fight_utils.py#L225) fixes the model to MC3-18, regardless of the README experiment table. The existing local adapter is preferable to upstream import-time dependencies, default pretrained downloads and unrestricted `torch.load`.
- **tiao:** [STE](https://github.com/tiao051/Violence-Detection/blob/40f8c5fd8be035bf8a1853edb45221f7ea39c5e1/ai_service/remonet/ste/extractor.py) stacks groups of three grayscale motion frames as channels, uses ImageNet-v1 2D backbones, and expects exactly 30 motion frames. [SME](https://github.com/tiao051/Violence-Detection/blob/40f8c5fd8be035bf8a1853edb45221f7ea39c5e1/ai_service/remonet/sme/extractor.py) actually uses RGB frame differences, dilation and thresholding, rather than the optical-flow description in some documentation. [Inference](https://github.com/tiao051/Violence-Detection/blob/40f8c5fd8be035bf8a1853edb45221f7ea39c5e1/ai_service/inference/inference_model.py#L169) defaults to MobileNet-v3-small, skips backbone validation when checkpoint metadata is absent, and loads head state with `strict=False`. [Training](https://github.com/tiao051/Violence-Detection/blob/40f8c5fd8be035bf8a1853edb45221f7ea39c5e1/ai_service/training/two-stage/train.py) defaults to MobileNet-v2. [GTE implementation](https://github.com/tiao051/Violence-Detection/blob/40f8c5fd8be035bf8a1853edb45221f7ea39c5e1/ai_service/remonet/gte/extractor.py) reads class 0 as violence, while earlier comments describe the opposite. Do not select an arbitrary head by filename or trust those comments; a strict checkpoint/backbone/data-label audit is still required. Checkpoints were not deserialized here.
- **VIGIl:** [backend model](https://github.com/ash-iiiiish/VIGIl.AI-Violence-WeaponDetectionTool/blob/7326719b6cf548b9a367355db803bfd3cd650066/backend/model.py) resizes BGR frames to 112 square, divides by 255 without RGB conversion, and gets ordered names from the missing checkpoint. A score above its lock threshold can keep a fight label active for the rest of the video. That is an alert-policy artifact, not evidence of continuous detection. The [actual LICENSE](https://github.com/ash-iiiiish/VIGIl.AI-Violence-WeaponDetectionTool/blob/7326719b6cf548b9a367355db803bfd3cd650066/LICENSE) is Apache-2.0, despite README MIT claims.
- **cvidgi:** [model](https://github.com/cvidgi/violence-detection-rwf2000/blob/8e296c3d9dd875b94a89b69468e46781c9ea5566/src/model.py), [loader](https://github.com/cvidgi/violence-detection-rwf2000/blob/8e296c3d9dd875b94a89b69468e46781c9ea5566/src/data.py), and [config](https://github.com/cvidgi/violence-detection-rwf2000/blob/8e296c3d9dd875b94a89b69468e46781c9ea5566/configs/baseline.yaml) establish an eight-frame RGB/ImageNet-normalized 2D mean-pooling baseline. Its synthetic stress analyses cannot establish real IR/night accuracy.

## Candidate 1: original Flow Gated Network

Author repository: [mchengny/RWF2000-Video-Database-for-Violence-Detection](https://github.com/mchengny/RWF2000-Video-Database-for-Violence-Detection/tree/1267a1208574af651dc2ea9b1439cb60b5a9fc54), commit **`1267a1208574af651dc2ea9b1439cb60b5a9fc54`**. This additional primary-author repository is a more concrete alternative than the unshipped R3D models above.

**Exact asset:** [Models/keras_model.h5](https://raw.githubusercontent.com/mchengny/RWF2000-Video-Database-for-Violence-Detection/1267a1208574af651dc2ea9b1439cb60b5a9fc54/Models/keras_model.h5), **1,208,192 bytes** from HTTP HEAD. Full checkpoint SHA-256 remains unmeasured. Raw ETag was `2bdc5be57b90b9a35fe89ba76184a7d1c5e5ea11ffe8fd97a0357d49f0248532`; treat it as an HTTP validator, not a substituted whole-file SHA-256.

To verify the artifact's actual architecture without loading it, fetched **only bytes 0–65535**, received HTTP 206, and parsed the HDF5 attribute's JSON as inert text. Range SHA-256: `e348b362dd312a5da7bc748a7ce9b84554a1480ede063a4f4a8a22c12604c24d` (only that 65,536-byte range). The embedded configuration confirms `[None,64,224,224,5]`, paired factorized Conv3D streams, multiplicative fusion, temporal pooling and **two-way softmax**. It also contains serialized Lambda functions, which were neither decoded as executable code nor executed.

**Reproduction contract:** [preprocessing notebook](https://github.com/mchengny/RWF2000-Video-Database-for-Violence-Detection/blob/1267a1208574af651dc2ea9b1439cb60b5a9fc54/Preprocess/Video2Numpy.ipynb) resizes with `INTER_AREA` to 224 square, converts BGR to RGB, computes Farneback flow between adjacent decoded frames, subtracts each component's spatial mean, then min-max scales each component to 0–255. Parameters are `(0.5,3,15,3,5,1.2,OPTFLOW_FARNEBACK_GAUSSIAN)`; final flow is zero-padded. RGB + x/y flow are stored as uint8. Its decode loop intentionally/accidentally omits the last source frame: preserve or explicitly version that difference in an adapter.

[Network/data-generator notebook](https://github.com/mchengny/RWF2000-Video-Database-for-Violence-Detection/blob/1267a1208574af651dc2ea9b1439cb60b5a9fc54/Networks/Flow%20Gated%20Network.ipynb) samples indices at `ceil(N/64)` spacing and pads to 64 using tail frames. Standardize RGB and flow separately over each complete group; use float32 channels-last. Disable training jitter/flip. A dynamic-crop helper exists but is not called in `load_data`; do not silently activate it.

**Class order/provenance blocker:** the generator sorts folder names ascending, implying **Fight=0, NonFight=1** for the supplied preprocessing folder layout. This is a source-derived mapping, not embedded checkpoint class metadata. The notebook's last training cells point to `ViolentFlow-opt`, rather than proving this exact H5 was trained on the RWF split behind the paper result. Author [load instructions](https://github.com/mchengny/RWF2000-Video-Database-for-Violence-Detection/blob/1267a1208574af651dc2ea9b1439cb60b5a9fc54/Models/Intro%20to%20pre-trained%20model.md) do not resolve that lineage. Record the mapping as provisional and verify it before scoring; do not attribute a paper percentage to these bytes.

**Executable path:** no clean inference CLI; the author supplies model loading, preprocessing and architecture in notebooks. Parent should rebuild the inspected graph with explicit channel slicing and load numeric weights, avoiding serialized Lambda execution. Do not run notebook training cells: they set four GPU devices and use obsolete `multi_gpu_model`. A safe reconstruction plus strict weight/shape validation is required before calling this locally runnable.

Total **4,075,957 bytes**. These are Git blob SHA-1 object identifiers, not file SHA-256 values. HEAD confirmed the variables payload exists at the pinned raw URL; no full payload or SavedModel was loaded. **Reproduction contract:** [prediction](https://github.com/Chewgithub/Fightdet/blob/e8745e464afe666287e39d2ef77c67025dd48dd6/Fightdet/predict.py) calls `make_prediction(model, video_path)` and expects `[1,64,224,224,3]`, returning a single sigmoid score with **1=Fight, 0=NonFight**. The [training generator](https://github.com/Chewgithub/Fightdet/blob/e8745e464afe666287e39d2ef77c67025dd48dd6/Fightdet/data_generator.py) uses reverse-sorted folders, consistent with that order. This differs from original FGN: never reuse its positive index.

[Video conversion](https://github.com/Chewgithub/Fightdet/blob/e8745e464afe666287e39d2ef77c67025dd48dd6/Fightdet/video_to_numpy.py) decodes the whole supplied clip, resizes to 224 square with `INTER_AREA`, converts BGR to grayscale and appends two [Farneback-flow channels](https://github.com/Chewgithub/Fightdet/blob/e8745e464afe666287e39d2ef77c67025dd48dd6/Fightdet/ysget_optical_flow.py). Flow parameters/scaling match the original pipeline, with a zero final flow. [Downsampling](https://github.com/Chewgithub/Fightdet/blob/e8745e464afe666287e39d2ef77c67025dd48dd6/Fightdet/down_sample.py) uses the same ceil-step/tail-padding policy; [processing](https://github.com/Chewgithub/Fightdet/blob/e8745e464afe666287e39d2ef77c67025dd48dd6/Fightdet/pre_processing_prediction.py) casts to uint8; [normalization](https://github.com/Chewgithub/Fightdet/blob/e8745e464afe666287e39d2ef77c67025dd48dd6/Fightdet/load_data_prediction.py) standardizes grayscale separately from the two flow channels.

Source [architecture](https://github.com/Chewgithub/Fightdet/blob/e8745e464afe666287e39d2ef77c67025dd48dd6/Fightdet/model.py): factorized 3D convolution streams, multiplicative gating, pooled merge layers and a one-unit sigmoid head. Source/SavedModel equivalence remains untested. Standardization lacks a zero-standard-deviation guard; static clips can create non-finite inputs. An adapter must reject/report that condition rather than report a normal prediction. The generic converter also has incomplete non-default branches; use only its inspected grayscale-plus-flow contract.

**Executable path:** this is the cleaner file-inference candidate. It still needs a pinned compatible TensorFlow runtime. Unbounded dependency versions in `requirements.txt` do not give a reproducible environment. Keras 3 does not load legacy SavedModel directories through `keras.models.load_model`; use an audited TF SavedModel inference endpoint or explicit reconstruction/weights mapping, without disabling arbitrary-code protections. [Keras migration documentation](https://keras.io/guides/migrating_to_keras_3/#loading-a-tf-savedmodel) explains this incompatibility.

## GTX 1660 Ti 6 GB / Windows assessment

**Inference feasibility is an estimate, not a measured result.** Batch-one FGN/Fightdet classification is plausible in 6 GB: each first 16-channel 64×224×224 float32 activation is about 196 MiB, with two streams plus intermediates/workspaces. Tiny weight files do not mean tiny activation memory. Full-res decoding buffers and CPU flow add host-memory/time costs; process only bounded windows, one decoder, `cv2.setNumThreads(1)`. No throughput, VRAM headroom alongside the live model, or p95 latency claim is justified yet.

FGN float32 input alone is approximately 61 MiB; Fightdet input is approximately 37 MiB. These are shape arithmetic, not memory profiles. Do not use their old training batch sizes or train them as part of this comparison.

[TensorFlow's official install guide](https://www.tensorflow.org/install/pip#windows-native) says 2.10 was the last release with native-Windows GPU support. Current TensorFlow GPU paths require a suitable separate environment such as WSL2; that environment is not authorized to be provisioned by this helper. NIVRA's inspected requirements are PyTorch 2.5.1 / torchvision 0.20.1 and contain no TensorFlow. Parent should first decide whether the isolated legacy-runtime/port cost is worthwhile. Do not alter the live venv to make these repos import. MC3 already has local compatibility evidence; the alternatives do not.

## Required comparison and exact unverified claims

1. **Artifact gate:** parent downloads only the selected pinned model files after resolving intended-use terms, computes full SHA-256 manifests, safely reconstructs/loads models, validates all weights/shapes and positive index, and records exact runtime versions. No automatic downloads or remote custom code. Test malformed, empty and static inputs as invalid/explicit outcomes.
2. **Comparable evidence:** use identical four-second source-time windows with each model's own preprocessing. FGN/Fightdet were designed around approximately five-second dataset clips, so document four-second duration shift. Do not prepend/append future frames. Freeze threshold, sampling, padding, cooldown and aggregation before diagnostics. A later five-second sensitivity comparison is a distinct predefined policy, not an opportunistic replacement.
3. **Crowd and quality gate:** all shortlisted models output one score per supplied scene/crop, without person tracks or interaction localization. No numeric person cap is evidence of coverage. A 1080p/720p view resized to 224 square may erase a small interaction. Measure scene alerts separately from localization and ROI coverage; record person pixel height, occlusion, skipped regions and alert delay under 50–100 visible people. Any tiling/ROI scheduler is a new unverified pipeline with its own miss/false-alert cost.
4. **Real-camera gate:** independently licensed native 1080p/720p recordings and explicitly compressed/degraded 480p copies, separately stratified for real near-IR monochrome CCTV and low-light colour, remain necessary. No inspected release provided a verifiable matching crowd/night holdout. RWF mentions dark/low-resolution cases but supplies no camera-spectrum/count-stratified validation here. Grayscale preprocessing is not true IR evidence; darkening daylight is not real night; thermal long-wave IR is a separate domain. Synthetic crowds/degradation establish only load/sensitivity.

**Shortlist:** original FGN and Fightdet gray+flow, with existing MC3 as control. **Blockers:** unspecified code/model permissions, FGN checkpoint lineage/class metadata, legacy TensorFlow/safe-loading work, and absent representative holdout. **Still empirically unverified:** any improvement over X3D-M in missed physical-fight events, false alerts per camera-hour, brief-contact recall, localization, true crowd/IR/low-light transfer, codec robustness, source-to-alert latency, sustained region/camera capacity and actual 6 GB co-residency. No model ranking or live-promotion recommendation follows from this audit.
